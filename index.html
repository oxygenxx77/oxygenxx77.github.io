我学的不是计算机，求职方向是运营和产品。秋招这段时间，每天都在重复几件事：翻岗位，判断值不值得投，把同一份简历填进一个又一个网申系统，再记住哪家的测评快截止了。

求职助手

采集岗位、AI 匹配、按公司推荐、辅助投递

当初的烦恼牛客上几百个岗位，一个个点开看 JD、对着简历判断值不值得投，一晚上也看不完几家。
  • AI 分三项打分：简历 50%、偏好 30%、城市 20%。最后的总分由后端加权，不让模型自己算
  • 按公司推荐：综合匹配分、岗位方向、城市、公司规模和岗位名称排序，方向可以写成「运营>营销=产品」这样的优先级
  • 对 AI 顾问说「把北京的岗位都标记为拒绝」，它会直接调用工具改数据
  • AI 调用失败会退避重试，实在不行就用本地规则打分；每天的投递数有上限，防止乱投
  • 「每家公司限投几个岗位」没让 AI 估：同一家公司问两次，给的数字都不一样，所以改成手填

用到：FastAPI · SQLite · OpenAI 兼容接口（function calling）· Chrome 扩展 MV3 · Swift / SwiftUI

秋招看板

管投递之后的事：测评截止、面试、等结果、Offer

当初的烦恼投了几十家以后，哪家测评快截止了、哪家约到了几面、哪家该去问进度，记在备忘录里全乱了。
  • AI 助手「小招」：说一句「美团约了二面，周五下午三点」，它就记下面试、改好状态
  • 每次 AI 改数据前先存快照，可以一键撤销；撤销前会检查这期间有没有别的改动
  • AI 回复「已更新」却没真的调用工具时，后端会自动追问一次，免得它只是嘴上答应
  • 日历订阅、微信提醒、周报、模拟面试
  • 数据同步到 SQLite，内置 SQL 练习题，还能和求职助手的岗位库跨库 JOIN

用到：FastAPI · JSON 原子写入 + 自动备份 · Chart.js · iCal · SQLite

简历自动填充

解析 PDF 简历，一键填网申

当初的烦恼每家公司的网申都要把同一份简历重新填一遍，教育、实习、项目得一条条点「添加」，学校和省市还是最难选的下拉框。

  • 和求职助手联动：认出当前岗位、让 AI 写文书、投完一键标记

我和 AI 合作的四条规矩

  1. 从自己卡住的地方出发

    每个功能都来自我求职时真的卡住的地方。做完马上自己用，好不好用，一天就知道。

  2. 用产品的话提需求

    讲清楚场景、想要的结果和边界情况（比如「腾讯」的岗位不能算到「腾讯音乐」头上），而不是告诉它代码怎么写。

  3. 带着证据排查问题

    出了 bug 先截图、写下复现步骤，让 AI 先找原因再动手改；改完我按原来的步骤再走一遍。

  4. 把规矩写下来

    设计上的取舍写进 README，隐私规则写成检查脚本和提交钩子，下次不用靠记性。

代码交给 AI 写；
做什么、为什么做、
做得对不对，
由我来判断。

踩过的坑

一次就写对的功能不多。更值得记下来的，是怎么发现问题、找到原因、做出取舍。

「确认投递」点了没反应？

现象
点了「确认投递」，岗位还停在「待投递」，我以为是 bug。
原因
这个按钮其实只是「加入待投递」，名字和行为对不上。
解决
改了名字，又加了「标记已投递」，在官网投过的岗位也能直接标记。问题出在交互的语义上，不在代码。

AI 说「已更新」，看板却没变

现象
小招偶尔回复「已经帮你改好了」，实际上什么都没改。
原因
模型有时直接用文字回答，跳过了工具调用。
解决
后端检测「说改了但没有成功的工具调用」，自动追问一次；每条修改都列在回复下面，可以核对，也可以撤销。

桌宠点了一直转圈

现象
双击桌宠后服务一直起不来，日志里也没有报错。
原因
项目放在「桌面」文件夹里，macOS 在后台等用户授权，Python 卡在读文件那一步。
解决
启动超过 6 秒，就提示去点系统弹窗里的「好」；顺手修了状态卡在「启动中」的问题。

限投数为什么不让 AI 估

想法
很多公司只让投 2～3 个岗位，想让 AI 查出来自动提醒。
实测
同一家公司连问两次，AI 给的数字都不一样。
取舍
改成手填，在卡片上放校招公告的链接方便查。不可靠的数据，不如没有。

「腾讯」不是「腾讯音乐」

需求
求职助手和看板要认出同一家公司：「广州小鹏汽车科技有限公司」就是「小鹏」。
坑
简单的包含匹配，会把「腾讯」的岗位算到「腾讯音乐」的卡片上。
解决
先去掉城市前缀和「有限公司 / 集团 / 科技」这类后缀再比，完全相同的优先，有歧义就不猜。

把工具开源，又不把自己泄露出去

问题
工具里全是真实的简历、投递记录和 API Key，代码里还写死了本机路径。
办法
白名单式的 .gitignore、本地隐私扫描器、提交前自动检查，再用假数据重新截图。
细节
旧的提交里带着本机路径和真实邮箱，于是重建了一份干净的提交历史。

开源之前做的事

这些工具每天处理的都是简历、联系方式和求职进度，所以把它们公开出来，这件事本身我也当成一个需求来做：

  1. 白名单式 .gitignore：默认忽略所有文件，只放行代码、示例和文档，以后新增的数据文件也不会被误提交
  2. 本地隐私扫描器：运行时从本机的简历和 .env 里读出敏感信息（姓名、电话、实习公司、Key），逐行比对要提交的文件；只报「文件:行号 + 类型」，不把隐私本身打印出来
  3. 提交前钩子：每次 git commit 都自动扫描，发现问题直接拒绝提交
  4. 假数据截图：求职助手和看板各带一个造数据的脚本，扩展截图用模拟的浏览器接口加一份虚构的简历；造数据脚本不会写进已有真实数据的目录
  5. 匿名身份：提交作者用 GitHub 的 noreply 邮箱，所有仓库以 MIT 许可证开源
隐私检查 · 提交前$ git commit -m "update" ✗ 发现 2 处疑似隐私信息 （只显示位置，不显示内容） a.py:1 本机路径（含用户名） resume.json 简历数据不应提交 确认是误报的行，加上 privacy-ok 注释即可跳过。$ git commit -m "init" ✓ 隐私检查通过 比对了 14 个本机敏感值 + 通用规则
