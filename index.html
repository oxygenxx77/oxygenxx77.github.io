How I Vibe Code

我怎么和 AI 一起写代码

AI 负责写代码，我负责「做什么、为什么、做得对不对」。

01

从真实痛点出发

每个功能都来自我自己求职时卡住的地方，做完马上自己用，好不好用一天就知道。

02

用产品语言提需求

讲清楚场景、期望结果和边界情况（比如「腾讯」不能算到「腾讯音乐」头上），而不是指定怎么写代码。

03

带着证据去排查

出 bug 时截图、描述复现步骤，让 AI 先定位原因再改；改完自己按原步骤验收。

04

把规则沉淀下来

设计取舍写进 README，隐私规则写成检查脚本和提交钩子，下次不靠记性。

Iteration Stories

迭代故事

比起一次写对，更能体现能力的是：发现问题、找到原因、做出取舍。

「确认投递」点了没反应？

现象
点「确认投递」后岗位还停在「待投递」，以为是 bug。
原因
按钮其实只是「加入待投递」，名字和行为对不上。
解决
改名，并新增「📮 标记已投递」，在官网投过的岗位也能直接标记。问题出在交互语义，而不是代码。

AI 说「已更新」，看板却没变

现象
小招偶尔回复「已经帮你改好了」，实际什么都没改。
原因
模型有时直接用文字回复，跳过了工具调用。
解决
后端检测「声称修改但没有成功的工具调用」，自动追问一次；每条修改都列在回复下方，用户能核对、能撤销。

桌宠点了一直转圈

现象
双击桌宠后服务一直起不来，日志里也没有报错。
原因
项目在「桌面」文件夹里，macOS 在后台等用户授权，Python 卡在读文件那一步。
解决
启动超过 6 秒就提示去点系统弹窗的「好」；顺手修了状态卡在「启动中」的问题。

限投数为什么不让 AI 估

想法
很多公司限投 2~3 个岗位，想让 AI 查出来自动提醒。
实测
同一家公司连问两次，AI 给的数字都不一样。
取舍
改为手填，并在卡片上放校招公告链接方便查。不可靠的数据不如没有。

「腾讯」不是「腾讯音乐」

需求
求职助手和看板要认出同一家公司：「广州小鹏汽车科技有限公司」就是「小鹏」。
坑
简单的包含匹配会把「腾讯」的岗位算到「腾讯音乐」的卡片上。
解决
去掉城市前缀和「有限公司 / 集团 / 科技」后缀再比，完全相同优先，有歧义时不猜。

把自己的工具开源，又不泄露自己

问题
工具里全是真实简历、投递记录、API Key，代码里还写死了本机路径。
方案
白名单式 .gitignore、本地隐私扫描器、提交前自动检查，再用虚构数据重新截图。
细节
旧提交里带着本机路径和真实邮箱，于是重建了干净的提交历史。
Shipping Safely

发布与隐私

工具每天处理的都是简历、联系方式和求职进度，所以「开源」这一步本身也当成一个需求来做：

  1. 白名单式 .gitignore：默认忽略一切，只放行代码、示例和文档，新增的数据文件不会被误提交
  2. 本地隐私扫描器：运行时从本机简历和 .env 读出敏感值（姓名、电话、实习公司、Key），逐行比对待提交的文件；只报「文件:行号 + 类型」，不把隐私打印出来
  3. 提交前钩子：每次 git commit 自动扫描，发现问题直接拒绝提交
  4. 虚构演示数据：求职助手和看板各带一个造数据脚本，扩展截图用模拟的浏览器接口加虚构简历；造数据脚本拒绝写入已有真实数据的目录
  5. 匿名提交身份：提交作者用 GitHub 的 noreply 邮箱
$ git commit -m "update" ✗ 发现 2 处疑似隐私信息（只显示位置，不显示内容）： a.py:1 本机路径（含用户名） resume.json 简历数据不应提交 确认是误报的行，加上 privacy-ok 注释即可跳过。 $ git commit -m "init" ✓ 隐私检查通过（比对了 14 个本机敏感值 + 通用规则）
